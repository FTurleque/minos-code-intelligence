## 4. Documentation, ADR et preuve réelle

- [x] 4.1 **(manuelle)** [AUD-SEC-02] Sous Linux (hôte ou conteneur avec réseau), `minos tools install scip-java` avec `MINOS_TEAM_KEY_TEST` posé dans l'environnement : l'installation réussit, `classpath.txt` correspond au verrou, et un `strace -f -e trace=execve -s 200` (ou `/proc/<pid>/environ` d'un processus fils pendant l'installation) ne montre pas la variable. Puis une installation avec un jar remplacé dans le cache (copie de test) échoue. Noter la sortie dans `SUIVI.md`. **Preuve (2026-10-13)** : Rejoué le 2026-10-13 sous Ubuntu 24.04.3 (WSL 2, noyau 6.18, Temurin 24.0.1, réseau), jar ombré construit le 2026-10-12 après la fusion des lots 1 et 2, Coursier `linux-x64` du catalogue (SHA-256 vérifié) dans le `PATH`, `MINOS_TEAM_KEY_TEST` et `GITHUB_TOKEN` posés dans l'environnement de MINOS. (a) `minos tools install scip-java` → code 0, « scip-java 0.13.1 — READY » ; `classpath.txt` : 74 jars, noms et SHA-256 identiques au verrou. (b) `/proc/<pid>/environ` de chaque processus descendant, lu toutes les 20 ms (`strace` absent de l'hôte) : 75 lectures, seule commande `cs fetch` (aucun `launch`), variables `HOME JAVA_HOME LANG LOGNAME PATH USER XDG_CACHE_HOME`, 0 lecture avec un secret. (c) un jar du cache Coursier (isolé par `XDG_CACHE_HOME`) modifié, installation rejouée de zéro → code 1, « scip-java classpath verification failed: scip-java-0.13.1.jar does not match its pinned SHA-256 », aucun `classpath.txt`. Limite : un processus de moins de 20 ms aurait pu échapper au relevé ; sans `JAVA_HOME`, la commande rend le code 1 (« machine prerequisite ») après avoir écrit le classpath vérifié.
