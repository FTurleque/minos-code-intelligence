# MINOS 1.0.1 — Windows Release Hardening

Statut : **CANDIDAT EN PRÉPARATION — NON PUBLIÉ**

Branche de travail : `fix/v1.0.1-release-hardening`

Aucun tag `v1.0.1` et aucune GitHub Release 1.0.1 ne doivent être créés avant validation locale et utilisateur du setup final.

## Objectif

1.0.1 est une maintenance corrective de la ligne 1.x. Elle corrige le packaging/runtime Windows et la qualité du parcours d'intégration MCP sans étendre les claims produit M25/M27/M28.

## P0 — runtime Java Windows complet

Cause du défaut 1.0.0 : le runtime `jpackage` était construit à partir d'une liste de modules trop étroite. Le MCP demandait notamment `org.w3c.dom.Node`, fourni par `java.xml`, absent de l'image embarquée.

Correction 1.0.1 :

```text
fat JAR exact
→ JDK 24 jdeps --multi-release 24 --ignore-missing-deps --print-module-deps
→ modules racines calculés
→ jpackage --add-modules <modules>
→ runtime/bin/java --list-modules
→ contrôle des racines
→ assertion java.xml
```

Le build ne corrige donc pas uniquement `java.xml` en dur : il suit les besoins réels du JAR final.

La liste effective est conservée dans :

```text
RUNTIME-MODULES.txt
```

et reportée dans `VERSION` via `runtimeModules=`.

## P0 — MCP packagé comme gate de release

La qualification exige désormais un vrai dialogue MCP :

```text
initialize
notifications/initialized
tools/list
```

avec vérification d'outils connus (`minos_search_code`, `minos_impact`).

Le handshake est exercé :

- sur la distribution ZIP installée ;
- sur une installation setup isolée.

Un simple `MINOS --version` ne suffit plus.

## P0 — smoke setup isolé

Le setup de production n'est plus installé automatiquement pendant un smoke local.

Le builder sait générer un setup non publiable de smoke avec :

- AppId distinct ;
- hooks PATH neutralisés ;
- configuration MCP neutralisée ;
- Docker neutralisé ;
- cleanup global neutralisé.

Ainsi, une validation locale ne doit pas modifier l'installation MINOS réelle du mainteneur.

## P1 — Wizard MCP détecté

Le setup 1.0.1 restaure une page dédiée :

```text
Intégrations MCP natives
Connecter le MCP natif MINOS à vos clients IA détectés
```

Les clients indisponibles sont désactivés et une raison est affichée.

Préflight :

- GitHub Copilot JetBrains / IntelliJ : détection application/config ;
- GitHub Copilot CLI : capability probe, rejet des launchers VS Code incompatibles ;
- Claude Code : capability probe MCP ;
- Claude Desktop : détection application/config ;
- OpenAI Codex : capability probe CLI ou mode Desktop/config utilisateur.

Les clients MCP ne sont plus des entrées statiques `[Tasks]` Inno Setup.

## P1 — Codex Desktop

Lorsque le préflight choisit le mode Desktop, MINOS gère un bloc marqué dans :

```text
%USERPROFILE%\.codex\config.toml
```

Le bloc est sauvegardé, idempotent et ownership-aware. Une section `mcp_servers.minos` non gérée n'est jamais écrasée.

## P1 — désinstallation MCP

La désinstallation :

- utilise les chemins CLI sauvegardés lorsque possible ;
- ne dépend pas uniquement du PATH courant ;
- conserve les entrées préexistantes ;
- conserve les entrées gérées qui ont été modifiées par l'utilisateur ;
- supprime uniquement les intégrations encore identifiables comme appartenant à MINOS.

## P2 — stderr MCP

Le shaded JAR de distribution inclut `slf4j-nop` afin d'éviter les warnings :

```text
SLF4J(W): No SLF4J providers were found.
```

Ce point n'était pas la cause du crash 1.0.0, mais nettoie stderr pour les clients MCP STDIO.

## Versioning

Ligne de développement :

```text
1.0.1-SNAPSHOT
```

La version release reste fournie par Maven CI-friendly :

```text
-Drevision=1.0.1
```

## Construction locale avant publication

Runner autoritatif pour le candidat utilisateur :

```text
scripts/release/build-local-windows-candidate.ps1
```

Il construit :

```text
target\dist\MINOS-1.0.1-windows-x64-setup.exe
target\dist\MINOS-1.0.1-windows-x64-setup.exe.sha256
target\dist\minos-1.0.1-windows-x64.zip
target\dist\minos-1.0.1-windows-x64.zip.sha256
```

Il ne publie rien, ne crée aucun tag et ne déclenche aucun GitHub Actions.

## Gates utilisateur avant publication

La publication 1.0.1 reste bloquée jusqu'à validation explicite :

1. le setup affiche correctement la page MCP détectée ;
2. le faux Copilot CLI/shim est désactivé ;
3. JetBrains/Claude/Codex sont décrits conformément aux logiciels réellement présents ;
4. installation dans le répertoire attendu ;
5. `minos.cmd --version` retourne 1.0.1 ;
6. Copilot démarre `app\minos.exe mcp` sans `NoClassDefFoundError` ;
7. MCP atteint l'état Connected ;
8. les tools MINOS sont visibles ;
9. désinstallation préserve les configurations tierces non détenues ;
10. autorisation explicite de publication.

## Non-objectifs

1.0.1 ne ferme pas #98 et ne revendique pas de sandbox OS réelle. Elle n'introduit ni nouveau provider majeur, ni SaaS opéré, ni nouveau backend sémantique.
