## Constats nouveaux (sprint 9)

**AUD-ARC-11** (Faible) — Règle A19 : retirer une entrée encore valide de la liste des adaptateurs embarqués lève leur protection sans que le garde le voie

- Preuve : scripts/architecture/check-module-boundaries.py:1176-1210 : A19 vérifie que chaque fichier qui nomme une API d'infrastructure figure dans INFRASTRUCTURE_API_USERS et qu'aucune source hors EMBEDDED_ADAPTER_CLASSES ne nomme une classe de cette liste, mais ne vérifie pas qu'une classe de INFRASTRUCTURE_API_USERS figure dans EMBEDDED_ADAPTER_CLASSES ; une entrée d'adaptateur n'est refusée comme périmée que si la classe n'existe plus (:1203). Mutation sur copie /tmp : suppression de `OllamaEmbeddingProvider` de embeddedAdapterClasses dans module-boundaries.json -> garde rc=0 (« 16 class(es) listed ») ; même mutation plus une référence `com.minos.application.semantic.OllamaEmbeddingProvider.class` ajoutée à MinosApplicationRuntimeConfiguration.java -> garde rc=0, alors que la même référence sans la suppression donne rc=1 (« A19 embedded adapters … names »). L'auto-test EmbeddedAdapterRuleTest (test_check_module_boundaries.py:1519-1587) n'a pas ce cas.
- Impact : La liste EMBEDDED_ADAPTER_CLASSES est une protection, pas une tolérance : sa réduction, présentée par ARCH-0087 comme le sens normal du cliquet (« les deux listes ne font que rétrécir »), suffit à autoriser la couche application à instancier de nouveau l'adaptateur HTTP ou l'analyseur javac. La garantie qui ferme AUD-ARC-01 repose alors sur la revue seule.
- Action : Dans A19, exiger que chaque classe de INFRASTRUCTURE_API_USERS (nom simple) figure dans EMBEDDED_ADAPTER_CLASSES, ou refuser le retrait d'une entrée dont la classe existe encore et nomme une API d'infrastructure ; ajouter le cas rouge correspondant à EmbeddedAdapterRuleTest.

**AUD-PERF-14** (Faible) — La table de symboles de l'explorateur survit à l'éviction de sa vue jusqu'au prochain accès à la WeakHashMap, qui n'a lieu qu'après le chargement de la vue suivante : les symboles de l'ancien snapshot restent retenus hors de tout compte

- Preuve : minos-application/src/main/java/com/minos/application/semantic/SemanticCorpusQueryService.java:79 (`Map<SnapshotReadView, SymbolLookup> lookups = new WeakHashMap<>()`), :405-424 (lookup : snapshots.loadActiveReadView(...) :411 est appelé AVANT le premier accès à lookups :417, seul site qui touche la map avec le put :422), :708-739 (SymbolLookup.of garde dans deux HashMap les objets Symbol du snapshot de la vue) ; une WeakHashMap tient ses valeurs par des références fortes et ne purge une entrée dont la clé est collectée qu'au prochain appel de l'une de ses méthodes ; sonde indépendante /tmp/wh/WeakLookupProbe.java (JDK 21.0.12, même forme : clé = vue qui tient les symboles, valeur = table des mêmes symboles) -> « view collected=true symbols still reachable before any map access=true », puis « symbols still reachable after a map access=false » ; le test SemanticCorpusQueryServiceTest.java:691-701 ne vérifie que la collecte de la vue, pas celle des symboles ; DATA-0085 point 19 affirme « elle ne survit pas à une vue évincée ».
- Impact : Le budget évince les vues en cache justement quand une nouvelle vue a besoin de place (QueryViewMemoryBudget.reserve -> evictCachedViews). Dans la JVM de l'explorateur, la requête suivante charge et décode la nouvelle vue (réservation, puis jusqu'à 34 % du tas de marge de décodage) pendant que les symboles de la vue évincée sont encore retenus par l'entrée périmée. Ce tas n'est compté ni par le budget, ni par une part de HeapShare, ni par la marge déclarée. Les symboles et leurs chaînes sont une part importante d'une vue. C'est le dépassement que DATA-0081/0085 veulent rendre impossible (OutOfMemoryError plutôt que refus explicite), pour une JVM proche de son budget. L'ampleur est calculée, pas mesurée.
- Action : Purger les entrées périmées avant de charger la vue (par exemple `synchronized (cacheLock) { lookups.size(); }` en tête de lookup, ou vider la map quand la vue rendue n'est plus celle de la table), ou ne garder qu'une table par projet, remplacée dès que la vue diffère. Étendre SemanticCorpusQueryServiceTest.anEvictedViewIsNoLongerReachableFromTheService : une WeakReference vers un Symbol de la vue évincée doit être collectée sans nouvel appel au service. Corriger la phrase de DATA-0085 point 19.
