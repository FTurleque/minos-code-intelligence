## Constat nouveau

**AUD-DEP-08** (Faible, sprint 5) — Portée calculée de la qualification Docker (PR #751) : un renommage d'un fichier de production vers src/test/ ou docs/ déclare la PR « non concernée », et le check exigé passe sans qualification

- Preuve : scripts/ci/plugin-gate.py:58 `git diff --name-only <base>...<head>` (rename detection active par défaut : seul le nouveau chemin est listé), réutilisé par scripts/ci/docker-gate.py:105 ; docker-gate.py:42-51 exclut `^[^/]+/src/test/` et `docs/` ; reproduction dans /tmp/rn/repo : `git mv minos-engine/src/main/java/com/minos/store/Cache.java minos-engine/src/test/java/com/minos/store/Cache.java` -> `git diff --name-only` liste seulement le chemin src/test, et `docker-gate.scope('pull_request', B, H, root=/tmp/rn/repo)` -> False ; scripts/ci/test_docker_gate.py : aucun cas de renommage (grep renam -> 0), 26 tests OK
- Impact : Une PR qui retire une classe de l'image en la déplaçant sous src/test/ ou docs/ saute la qualification Docker A -> B, et le check exigé « Docker upgrade evidence gate » passe (« non concerné »). Cela contredit la règle annoncée (« tout doute répond concerné »). Les builds Verify tournent quand même.
- Action : Lire le diff avec `--name-status --no-renames` (ou `--no-renames` sur `--name-only`) pour que l'ancien chemin d'un renommage ou d'une suppression compte dans la portée ; ajouter le cas « renommage src/main -> src/test » et « src/main -> docs/ » à test_docker_gate.py.
