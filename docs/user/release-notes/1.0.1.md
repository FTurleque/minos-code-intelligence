## Défaut corrigé depuis 1.0.0

Le runtime Windows 1.0.0 pouvait échouer au bootstrap MCP avec :

```text
java.lang.NoClassDefFoundError: org/w3c/dom/Node
```

Le runtime 1.0.1 est dérivé du fat JAR exact avec JDK 24 :

```text
fat JAR
→ jdeps --print-module-deps
→ jpackage --add-modules
→ runtime/bin/java --list-modules
→ contrôle des modules racines
→ assertion java.xml
```

`RUNTIME-MODULES.txt` et `VERSION` conservent les preuves de provenance du runtime.

## Correctifs issus de la validation utilisateur réelle

Les essais sur le poste Windows du mainteneur ont conduit aux derniers correctifs avant publication :

- **Codex Desktop** : un ancien bloc explicitement marqué MINOS est sauvegardé puis réparé si l'état d'ownership historique a divergé ; une section non marquée reste protégée ;
- **Docker local** : le candidat peut préconstruire l'image provider-complete une seule fois et le setup la réutilise uniquement si ses labels version/commit/provider correspondent exactement ;
- **PowerShell 5.1** : `docker image inspect` est parsé en JSON via `ConvertFrom-Json`, sans Go template fragile ;
- **build local répétable** : seuls les processus dont l'exécutable réside sous le staging jetable `target\dist` peuvent être arrêtés avant nettoyage ; aucun `java.exe` global n'est tué.

## Désinstallation et ownership

La désinstallation :

- supprime uniquement les intégrations encore détenues par MINOS ;
- préserve les entrées tierces ;
- conserve `%LOCALAPPDATA%\MINOS` par défaut ;
- propose une purge explicite en mode interactif ;
- ne supprime jamais une base PostgreSQL externe ;
- neutralise la purge et les mutations globales dans les smokes automatisés.
